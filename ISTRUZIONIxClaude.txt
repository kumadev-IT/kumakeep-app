## App: KumaKeep
**Package:** `com.kumadev.kumakeep`  
**Descrizione:** Gestore personale di collezione board game per Android — alternativa leggera e mobile-first a BoardGameGeek, per uso personale single-user.

### Filosofia prodotto
- La collezione e le liste dell'utente sono **entità completamente separate da BGG** — BGG è solo fonte dati per ricerca e dettagli
- App **offline-first**: i dati vivono in Room, BGG è solo consultato on-demand
- **Single-user**: nessun concetto di userId ovunque
- UI minimalista per esperti: no informazioni ridondanti, info essenziali a colpo d'occhio

## Database Schema (Room)

### `BoardGameEntity` — cache dati BGG
Campi: `id`, `bggId` (unique), `primaryName`, `alias`, `yearPublished`, `minPlayers`, `maxPlayers`, `minAge`, `playingTime`, `complexity` (float 1-5), `bggRating` (float), `thumbnail`, `image`, `description`, `designers`, `artists`, `publishers`, `categories`, `mechanics`, `families` (tutti CSV string), `createdAt`, `updatedAt`

### `LibraryEntity` — collezione utente
Campi: `id`, `bggId` (FK → BoardGameEntity, CASCADE), `rate` (enum UserRate), `numPlays` (enum NumPlays), `notes`, `createdAt`, `updatedAt`

### `WishlistEntity` — liste wishlist (named)
Campi: `id`, `name` (unique), `description`, `createdAt`

### `WishlistEntryEntity` — giochi nelle wishlist
Campi: `id`, `wishlistId` (FK → WishlistEntity, CASCADE), `bggId` (FK → BoardGameEntity, CASCADE), `toBuy` (Boolean flag), `notes`, `createdAt`

### Enum
```kotlin
enum class UserRate { BAH, MID, YES, TOP, WOW, NOT_RATED }
enum class NumPlays { ZERO, ONE, MANY, PLENTY, NOT_CLASSIFIED }
```

## BGG API
- **Base URL:** `https://boardgamegeek.com/xmlapi2/`
- **Auth:** Bearer token in header `Authorization`
- **Token:** gestito via `local.properties` → `BuildConfig.BGG_TOKEN`
- **Headers:** `Authorization: Bearer <token>`, `User-Agent: KumaKeep/1.0 (Android; kumadev.code@gmail.com)`, `Accept: application/xml`
- **Endpoints usati:**
  - `GET /search?query=<q>&type=boardgame` → `BggSearchResponse`
  - `GET /thing?id=<id>&type=boardgame&stats=1` → `BggThingResponse`
- **Nota:** tutte le liste nei DTO usano `MutableList` con `mutableListOf()` (non `emptyList()`) per compatibilità SimpleXML

## Linee guida sviluppo
1. **Clean Architecture strict:** domain non importa nulla da data/presentation
2. **Single-user:** mai usare userId
3. **Flow reattivo:** le query Room restituiscono `Flow<T>`, le scritture sono `suspend fun`
4. **KSP** (non kapt) per Room e Hilt
5. **Coroutines** sempre su `viewModelScope`, mai operazioni su main thread
6. **UiState sealed interface** per ogni schermata (Loading/Success/Error/Empty)
7. **UseCase** con `operator fun invoke` per chiamata diretta
8. **OnConflictStrategy.REPLACE** per BoardGameDao (cache BGG), **ABORT** per LibraryDao/WishlistDao
9. **DTO SimpleXML:** tutte le liste devono essere `MutableList` con `mutableListOf()`
10. **Enum TypeConverter:** salvati come String (`.name`), deserializzati con `firstOrNull ?: default`
11. **Token BGG:** mai hardcodato, sempre da `BuildConfig.BGG_TOKEN` → `local.properties`
